# 🧭 Better Art Direction для Codex

**Better Art Direction** — Codex-native навык для разработки, аудита и переработки интерфейсов, которые связаны с реальным продуктом и не выглядят как взаимозаменяемый ИИ-шаблон.

Навык не заменяет один модный шаблон другим. Он сначала определяет назначение продукта, аудиторию, режим интерфейса, плотность, композиционную логику и один осмысленный выразительный приём, а затем проверяет результат в работающем интерфейсе.

## ✨ Что умеет

- формирует арт-направление до начала широкой верстки;
- проводит доказательный аудит существующего интерфейса без изменения кода;
- перерабатывает внешний и структурный слой, сохраняя маршруты, данные и бизнес-логику;
- полирует зрелую дизайн-систему без бессмысленного сноса;
- извлекает переносимые принципы из скриншота или ссылки без пиксельного копирования;
- различает операционные, аналитические, научные, потребительские, редакционные и рекламные поверхности;
- выявляет карточный шум, рекламную композицию в рабочих системах, фиктивные метрики, декоративную псевдоструктуру и другие типовые признаки шаблонной генерации;
- проверяет реальные размеры экрана, переполнение, обрезанный текст, доступные имена, подписи форм, сетевые и консольные ошибки;
- взаимодействует с `better-interface`, `better-layout`, `better-typography`, `better-colors`, `better-ui`, `better-accessibility` и `better-writing`, если они установлены.

# 🚀 Подключение к Codex

## Вариант 1. Плагин через marketplace — рекомендуемый для Codex CLI

Добавьте репозиторий как источник плагинов:

```bash
codex plugin marketplace add f2re/better-art-direction --ref main
codex plugin marketplace list
```

Затем в Codex:

```text
/plugins
```

Выберите marketplace **f2re · Better Art Direction**, установите плагин `better-art-direction` и начните новую сессию Codex.

Обновление подключённых marketplace:

```bash
codex plugin marketplace upgrade
```

> Плагин доступен в поддерживаемых plugin-поверхностях Codex CLI и ChatGPT/Codex desktop. Для Codex IDE extension используйте прямую установку навыка ниже.

## Вариант 2. Установка навыка в профиль пользователя

Codex загружает пользовательские навыки из `$HOME/.agents/skills`.

### Linux и macOS

```bash
git clone --depth 1 https://github.com/f2re/better-art-direction.git
cd better-art-direction
./scripts/install-skill.sh --user --copy --force
```

Для разработки удобнее символическая ссылка: изменения в клоне становятся доступны без повторного копирования.

```bash
./scripts/install-skill.sh --user --link --force
```

### Windows PowerShell

```powershell
git clone --depth 1 https://github.com/f2re/better-art-direction.git
Set-Location better-art-direction
pwsh ./scripts/install-skill.ps1 -Scope User -Mode Copy -Force
```

При включённом режиме разработчика Windows можно использовать ссылку:

```powershell
pwsh ./scripts/install-skill.ps1 -Scope User -Mode Link -Force
```

## Вариант 3. Навык только для одного проекта

Проектные навыки размещаются в `.agents/skills` внутри репозитория.

### Linux и macOS

```bash
git clone --depth 1 https://github.com/f2re/better-art-direction.git /tmp/better-art-direction
/tmp/better-art-direction/scripts/install-skill.sh \
  --project /путь/к/вашему-проекту \
  --copy \
  --force
```

### Windows PowerShell

```powershell
git clone --depth 1 https://github.com/f2re/better-art-direction.git "$env:TEMP\better-art-direction"
pwsh "$env:TEMP\better-art-direction\scripts\install-skill.ps1" `
  -Scope Project `
  -Project "C:\путь\к\вашему-проекту" `
  -Mode Copy `
  -Force
```

Итоговый путь:

```text
<проект>/.agents/skills/better-art-direction/SKILL.md
```

# 🛠 Использование

Навык поддерживает пять режимов.

## 1. `direction` — новое арт-направление

```text
$better-art-direction direction
Определи арт-направление для интерфейса оперативного метеоролога.
Сначала изучи репозиторий, реальные данные, пользователей и ограничения.
Код пока не меняй.
```

Результат: продуктовая основа, режим интерфейса, визуальный тезис, выразительный приём, композиция, роли типографики и цвета, движение, антиориентиры, карта реализации и план проверки.

## 2. `audit` — аудит без изменений

```text
$better-art-direction audit full
Проверь интерфейс целиком. Найди признаки шаблонной ИИ-композиции,
несоответствие режиму продукта и подтверждённые проблемы в браузере.
Код не меняй.
```

Результат: область проверки, доказательства, приоритетные находки, отклонённые ложные кандидаты, выполненные проверки и итоговый вердикт.

## 3. `redesign` — переработка интерфейса

```text
$better-art-direction redesign экран управления сотрудниками.
Сохрани маршруты, API, данные и информационную архитектуру.
Исправь композицию, плотность, иерархию и состояния, затем проверь браузером.
```

## 4. `polish` — полировка без смены системы

```text
$better-art-direction polish форму импорта.
Сохрани текущие токены и компоненты. Устрани подтверждённые проблемы,
сделай снимки до и после и перечисли фактически выполненные проверки.
```

## 5. `study` — изучение референса

```text
$better-art-direction study этот скриншот.
Выдели макроструктуру, характер типографики, плотность и один сильный приём.
Отдели переносимые принципы от уникальных материалов исходного продукта.
Ничего не копируй пиксельно.
```

# 🔍 Статический аудит исходников

`static-audit.mjs` работает без npm-зависимостей и проверяет HTML, CSS, JS/TS, JSX/TSX, Vue, Svelte, Astro и MDX.

Пользовательская установка:

```bash
node "$HOME/.agents/skills/better-art-direction/scripts/static-audit.mjs" src
```

Отчёт Markdown:

```bash
node "$HOME/.agents/skills/better-art-direction/scripts/static-audit.mjs" src \
  --format markdown \
  --out reports/art-direction-static.md
```

Строгий режим для CI:

```bash
node "$HOME/.agents/skills/better-art-direction/scripts/static-audit.mjs" src --strict
```

Проверяются, в частности:

- удалённый без замены фокус;
- кнопки только с иконкой без доступного имени;
- `transition: all`;
- вложенные карточки;
- фиктивные метрики и социальные доказательства;
- одинаковые `Learn more` / «Подробнее»;
- декоративные `SECTION 01`;
- фальшивая рамка браузера или устройства;
- цветовой и радиусный разнобой вне слоя токенов;
- `h-screen` / `100vh` как риск мобильного viewport;
- пустые состояния без следующего действия;
- распространённые шаблонные градиенты, стекло и свечения — как эвристика, а не автоматический запрет.

Коды правил начинаются с `BAD` — **Better Art Direction**.

# 🖥 Браузерный аудит

Помощник использует Playwright и, при наличии, `axe-core` из **проверяемого проекта**. Сначала установите их в этом проекте:

```bash
npm install --save-dev playwright axe-core
npx playwright install chromium
```

Запустите приложение, затем аудит:

```bash
node "$HOME/.agents/skills/better-art-direction/scripts/visual-audit.mjs" \
  --url http://127.0.0.1:3000 \
  --paths /,/settings,/employees \
  --widths 320,375,414,768,1440 \
  --schemes light,dark
```

Для офлайн-системы с уже установленным Chromium можно не скачивать браузер Playwright:

```bash
npm install --save-dev playwright-core
node "$HOME/.agents/skills/better-art-direction/scripts/visual-audit.mjs" \
  --url http://127.0.0.1:3000 \
  --executable-path /usr/bin/chromium \
  --no-axe
```

Путь также можно передать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Результаты сохраняются в:

```text
.art-direction-audit/
├── report.json
├── report.md
└── screenshots/
```

Автоматически проверяются:

- горизонтальное переполнение;
- возможная обрезка текста;
- доступные имена элементов управления;
- подписи полей;
- `alt` у изображений;
- повторяющиеся `id`;
- слишком маленькие области взаимодействия;
- крупные перекрывающие fixed/sticky-слои;
- консольные, сетевые и HTTP-ошибки;
- длительное движение при `prefers-reduced-motion: reduce`;
- WCAG-нарушения, которые находит `axe-core`.

Строгий режим:

```bash
node "$HOME/.agents/skills/better-art-direction/scripts/visual-audit.mjs" \
  --url http://127.0.0.1:3000 \
  --strict
```

> Автоматический аудит не решает, подходит ли дизайн конкретному продукту. Снимки, основной пользовательский сценарий, клавиатура, реальные тексты и предметная специфика остаются обязательной ручной частью проверки.

# 🧩 Совместная работа с другими `better-*` навыками

`better-art-direction` владеет только общим направлением:

| Область | Владелец |
| --- | --- |
| Предметная основа, макроструктура, выразительный приём, плотность, образный язык, тезис движения | `better-art-direction` |
| Группировка, выравнивание, интервалы, адаптивность | `better-layout` |
| Шрифты, шкала, переносы, рендеринг текста и чисел | `better-typography` |
| Палитра, семантические роли, gamut, измерение контраста | `better-colors` |
| Поверхности, иконки, микровзаимодействия | `better-ui` |
| Семантика, клавиатура, фокус, формы, zoom, reduced motion | `better-accessibility` |
| Терминология, кнопки, ошибки и пустые состояния | `better-writing` |
| Сводный междисциплинарный аудит | `better-interface` |

Если соседние навыки не установлены, `better-art-direction` не изображает их полный аудит. Он отмечает непроверенную область и продолжает в пределах собственной компетенции.

# 🧠 Основные принципы

1. **Сначала продукт, затем стиль.** Интерфейс выводится из задачи, данных, аудитории и условий работы.
2. **Не заменять шаблон шаблоном.** Нет запрета на Inter, карточки, градиенты, Bento или антикву как таковые.
3. **Один сильный приём.** Выразительность концентрируется в одном месте, остальное остаётся дисциплинированным.
4. **Структурное разнообразие важнее перекраски.** Разные продукты не должны иметь одну и ту же последовательность секций.
5. **Реальные данные вместо декораций.** Никаких выдуманных процентов, клиентов, отзывов и функций.
6. **Сначала доказательство.** Визуальный дефект подтверждается отрисованным состоянием, кодовый — точным местом в исходниках.
7. **Честная проверка.** Непроверенный экран или viewport не объявляется проверенным.
8. **Сохранение продукта.** Редизайн не даёт права молча ломать маршруты, поведение или владельцев компонентов.

# 🧪 Разработка и проверка репозитория

Требуется Node.js 20 или новее.

```bash
git clone https://github.com/f2re/better-art-direction.git
cd better-art-direction
npm ci
npm run check
npm run audit:self
```

Команды:

| Команда | Назначение |
| --- | --- |
| `npm run validate` | структура навыка, manifest, marketplace, ссылки, frontmatter, JSONL и синтаксис скриптов |
| `npm test` | правила статического аудита, CLI и установщик |
| `npm run check` | полная обязательная проверка |
| `npm run audit:self` | контроль отсутствия ложных срабатываний на чистом эталонном интерфейсе |
| `npm run audit:fixture` | демонстрационный отчёт по намеренно плохому примеру |

GitHub Actions запускает `npm run check` и самопроверку при каждом pull request и обновлении `main`.

# ⚖️ Ограничения

- Эвристический сигнал не является автоматическим дизайнерским приговором.
- `axe-core` не заменяет ручную проверку клавиатуры и вспомогательных технологий.
- Снимок не подтверждает динамическое поведение без взаимодействия.
- Из URL без исходников нельзя достоверно вывести внутренние токены, владельцев компонентов и намерения команды.
- Навык не должен копировать чужие защищённые материалы, платные шаблоны и фирменные активы.

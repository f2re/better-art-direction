# Участие в разработке

## Перед изменением

1. Определите, относится ли правило к арт-направлению продукта или к отдельной дисциплине: компоновке, типографике, цвету, доступности, текстам либо микровзаимодействиям.
2. Размещайте правило только у владельца области. В `better-art-direction` должны оставаться продуктовая специфика, макроструктура, выразительный приём, плотность, образный язык и общая логика движения.
3. Для новой эвристики опишите, почему она является сигналом, а не универсальным запретом.

## Локальная проверка

```bash
npm ci
npm run check
npm run audit:self
```

Для браузерного помощника создайте отдельный тестовый проект:

```bash
npm install --save-dev playwright axe-core
npx playwright install chromium
node /path/to/better-art-direction/skills/better-art-direction/scripts/visual-audit.mjs \
  --url http://127.0.0.1:3000 \
  --paths /,/settings \
  --widths 320,768,1440
```

## Изменения правил

- Добавьте или обновите сценарий в `quality/scenario-evals.md`.
- При изменении описания навыка обновите `quality/trigger-evals.jsonl`.
- При изменении формата файлов обновите `scripts/validate-repo.mjs`.
- Не включайте в репозиторий снимки чужих продуктов и защищённые авторским правом макеты.
